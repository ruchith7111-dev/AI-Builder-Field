# 01 · Mistakes & false starts

AI can generate a convincing answer before it has understood the actual problem. These notes focus on failure patterns that are easy to miss when a prototype appears to move quickly.

These are **general engineering traps**, not claims that every one happened in a particular project.

## Read in this order
1. [Starting with a vague request](vague-prompts.md)
2. [Asking for too much in one change](oversized-changes.md)
3. [Trusting plausible output](plausible-output.md)
4. [Skipping verification](skipping-verification.md)
5. [Losing context between sessions](context-drift.md)
6. [Confusing a demo with a dependable feature](demo-vs-product.md)

For each mistake, ask: What signal should have warned me? What small action would expose the risk? What evidence would justify proceeding? What should be recorded so the same issue is easier to catch next time?

**Rule:** AI output is a proposal. The engineer owns the decision.
